# IR取得・投稿の譜面解釈を揃える（source-only）

Refs #351, #485, BMS-Mania/bms-ir-plugin#65。配布基準は本体0.4.14.120
(`1c1ad366`)、plugin0.0.81 (`dd854c3`)。この変更だけでは配布しない。

孤立したLNOBJを可視通常ノートにするparser revision3を使う。
`#LNOBJ ZZ / #01024:ZZ94` のように先行する可視ノートがない場合が対象。
不可視ノートは始点に使わない。通常LN・連続終端の既存処理は維持する。

公開MD5/SHA-256は元ファイルのまま。新しく解釈が変わる譜面の成績・リプレイは
`bmsir-parser-v3:` のローカルキーで旧解釈と分離する。revision2だけの修正は
従来のv2キーを維持する。旧リプレイのrevision1/2を復元でき、旧PBを現在の
ノーツ数へ移動しない。RANDOMの各分岐で保存キーが変わらないよう保守的に分離する。

catalog metadataは1=rev1、2/3=rev2通常/影響あり、4=rev3通常、5=rev3でも
v2修正のみ、6=新しい孤立終端、7=孤立終端とv2修正の両方。通常の指定範囲の
再スキャンで旧metadataを更新し、ライブラリ全体の強制再構築はしない。

ランキングは読込済みモデルとカタログのMD5/SHA-256を照合する。未読込の
RANDOM譜面は分岐を推測せず未解決にし、別分岐のcacheを復元・表示しない。
コース投稿スナップショットは実プレイに用いた各モデルから作り、カタログの
古いノーツ数を使わない。スナップショット作成時のファイルI/Oは追加しない。

IRChartData/IRCourseDataの任意フィールド `bmsirScoreSha256` は、その譜面または
コースのローカル成績キーを表す。公開曲キーとは別で、投稿先を生成するためには
使わない。対応pluginは、実効LN種別・ノーツ数・公開/ローカル成績identityが
スナップショットと合うことを投稿前に確認する。旧pluginはフィールドを無視する。

旧1433群の実績の修復・再分類・再投稿は行わない。公開1434群へ数だけ書き換えて
移す処理や、ノーツ数照合の解除は含まない。実機受入はoperatorが行う。
