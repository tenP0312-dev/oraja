# 手元カメラをスキンに表示する

Arena oraja本体は手元カメラをローカルで取得し、JSON/Luaスキンの `camera` 部品へ
表示できます。実装Issueは [#480](https://github.com/tenP0312-dev/oraja/issues/480) です。
これはsource実装の説明です。配布済みのバージョンに追加されたという意味ではありません。

## 本体設定

起動前コンフィグの「画面 / Video」にある「手元カメラ」を使用します。
クラシックとサイドバーの両方に同じ設定があります。

1. 「カメラ一覧を更新」を押し、使用するカメラを選択します。
2. カメラが対応する幅・高さ・FPSを指定します。初期値は640×480 / 30 FPSです。
3. 必要なら「左右反転」をONにし、「手元カメラを有効にする」をONにします。
4. 保存し、`camera` 部品を持つスキンで本体を起動します。

初期OFFです。ランチャーはカメラ一覧を更新するまではデバイスを列挙せず、ONでもデバイス
未選択なら取得しません。一覧から選んだカメラは、名前とOSの固有ID（Windowsは
DirectShowのAlternative name。macOSのFFmpegは固有IDを出さないため名前のみ）を
`handCameraDeviceName` / `handCameraDeviceId` に保存し、次回以降は選び直さずに使えます
（[#519](https://github.com/tenP0312-dev/oraja/issues/519)）。

本体はカメラを開くたびに取得用ワーカーでデバイスを列挙し、ID、次に名前で保存したカメラを
探して、その時点の入力値（macOSのAVFoundation番号、WindowsのDirectShow名）で開きます。
そのため接続順やmacOSの番号が変わっても同じカメラにつながります。Windowsで同じ名前の
カメラが複数あるときは固有IDで開き、そのカメラが見つからなければ同名の別のカメラは
使いません。名前が一つだけのカメラは、USBポートを変えてIDが変わっても名前で見つけます。
保存したカメラが見つからない、または同名のカメラを区別できないときは取得せず、
別のカメラにはつなぎません。ランチャーで一覧を更新すると、保存したカメラを同じ照合で
選択した状態に戻し、手動で選び直すこともできます。

名前を保存していない旧設定や、手入力した値は従来どおり保存値（WindowsはDirectShowの
カメラ名、macOSはAVFoundationの番号、Linuxは `/dev/videoN`）をそのまま使います。
一度一覧から選んで保存すると名前で照合するようになります。

解像度・FPSが非対応、OS権限拒否、カメラ取り外し等で取得できないときは映像だけを
非表示にしてゲームを続行します。ゲームのログには手元カメラが利用できない旨を一度だけ残し、
待機中の再試行は記録しません（再接続したときは接続した旨を残します）。

コントローラーと同じように、カメラ部品を表示している画面（プレイ中を含む）では、
未接続・取り外し・停止したカメラを裏で開き直します。後から挿したカメラや挿し直した
カメラは、画面を出入りしなくても自動で映ります。開き直しは取得用ワーカーで行い、描画を
待たせません。毎フレームは試さず、失敗が続くと2秒、4秒、8秒、以降10秒ごとに間隔を
広げます。映像を一度でも取得できていたカメラが止まった場合は2秒後から試します。
設定を変更したとき、またはカメラ部品のない画面へ戻って再入場したときはすぐに試します。
カメラ部品のない画面では列挙も開き直しもしません。保存したカメラを名前・IDで探すため、
別のカメラを挿してもそちらにはつながりません。起動／フレーム取得の停止が10秒続くと
その取得を終了し、上の間隔で開き直します。停止した映像は最後の取得から1秒を過ぎると
表示しません。プレイ中の開き直しはFFmpegの子プロセスを起動するため、実機での描画負荷・
音切れの確認対象です。

OSのカメラ許可が必要です。macOSの配布ランチャーには
`NSCameraUsageDescription` の用途説明が必要です。
[Rancher #52](https://github.com/tenP0312-dev/oraja-Rancher/issues/52) がこれを追加し、
本体の配布ツールは用途説明がないmacOSランチャーを拒否します。ランチャー・Java・FFmpeg子プロセス
を経由した実際の権限表示・拒否時動作はoperatorによる確認対象です。
Windowsではデスクトップアプリのカメラアクセス許可を確認してください。

## camera部品のないスキン（BGA枠に表示）

「BGA枠に表示する」をONにすると、camera部品のないプレイスキンでも、BGA枠にBGAの代わりに
手元カメラを映します（[#521](https://github.com/tenP0312-dev/oraja/issues/521)）。スキンの変更は不要です。
位置・大きさ・表示条件はスキンのBGA枠、拡大方法は「BGAの拡大方法」、左右反転は手元カメラの
設定に従います。カメラが映らない間（未接続、抜いた直後、最初のフレームの前）は通常のBGAを
表示し、映ると切り替わります。BGAへ戻せるよう、BGAの読み込み・デコードは今まで通り行うため、
BGAの負荷は減りません。練習モードではBGA枠に練習設定が出るため、カメラは映しません。
camera部品を持つスキン（例: IIDX33の「Hand Camera」を有効にした状態）では、ONでもBGA枠には
通常のBGAを表示し、カメラの位置はスキンに任せます。両方に同じ映像が二重に出ないようにする
ためです（[#525](https://github.com/tenP0312-dev/oraja/issues/525)）。

## 表示位置・拡大率・切り抜きの調整

本体設定で、すべてのカメラ表示（スキンのcamera部品とBGA枠）の位置と映す範囲を調整できます
（[#526](https://github.com/tenP0312-dev/oraja/issues/526)）。ランチャーの「画面 / Video」と、F5の
「手元カメラ」ウィンドウのどちらからでも変更できます。F5での変更はカメラを開き直さずに次の
フレームから反映するので、プレイ中に見ながら合わせられます。

| 項目 | 意味 | 範囲（初期値） |
| --- | --- | --- |
| 表示位置X / Y | 表示枠の幅・高さに対するずらし量。Xは正で右、Yは正で下 | -100〜100%（0） |
| 拡大率 | 100で全体、200で半分の範囲を拡大 | 100〜400%（100） |
| 切り抜き中心X / Y | 拡大したときに映す場所の中心。表示している（左右反転後の）映像に対する位置 | 0〜100%（50） |

拡大と切り抜きは、スキンが指定する切り抜き（例: IIDX33の帯）の内側で行い、元の映像の外は
読みません。表示枠からはみ出した部分の扱いは通常のスキン部品と同じです。

## ゲーム中の変更（F5メニュー）

F5のModメニューの「手元カメラ」ウィンドウで、有効・無効、BGA枠に表示、使用するカメラ
（「カメラ一覧を更新」で列挙）、サイズ、FPS、左右反転を変更できます。ランチャーと同じ設定を
編集し、変更は次のフレームから反映します（カメラやサイズを変えると開き直します）。
サイズとFPSはよく使う値と現在の値から選びます。それ以外の値はランチャーで指定します。
設定は通常どおり終了時とプレイ外の定期保存で保存します。状態欄には映像を受信中か、
接続待ちかを表示します。

## JSONスキン

次の二つを**プレイスキンだけ**へ追加すると、そのスキンの座標系の右上に表示できます。
以下は1280×720の例です。描画順は通常の `destination` 配列順です。
枠やマスク風の装飾は既存の画像部品を上に重ねられます。

```json
{
  "camera": [
    { "id": "hand-camera" }
  ],
  "destination": [
    {
      "id": "hand-camera",
      "stretch": 3,
      "dst": [{ "time": 0, "x": 940, "y": 520, "w": 320, "h": 180 }]
    }
  ]
}
```

これは追加部分の例で、単独の完全なスキンではありません。
選曲・リザルトのスキンへ `camera` を追加しなければ、その画面では取得しません。
READY以降、PLAY中だけなどの条件は通常の `destination.timer`、`op`、`draw` を使用します。
完全透明、非表示、描画サイズがゼロ以下の部品も取得を要求しません。
スキン選択のライブプレビューではカメラを開きません。

スキンはデバイス・本体のON/OFF設定を変更できません。`camera` は本体で選んだ一つの
カメラを共有します。複数の部品へ同時表示してもデバイスは一つです。
`id` は他の部品と重複させないでください。

| 項目 | 意味 | 初期値 |
| --- | --- | --- |
| `id` | `destination` が参照する部品ID | 必須 |
| `cropX`, `cropY` | 切り抜き始点。元映像の左上が0,0、右下が1,1 | 0,0 |
| `cropWidth`, `cropHeight` | 元映像に対する切り抜き幅・高さ | 1,1 |

切り抜きは左右反転より先に適用します。全項目は有限値で、始点0以上、サイズ0より大きく、
切り抜きが元映像を超えない範囲です。不正な範囲の部品は読み込み時に無効になります。

拡大方法は通常の `destination.stretch` を使います。未指定は縦横比を保って内側へ収める
`1`、領域いっぱいに中央を切り抜くなら `3`、引き伸ばすなら `0` です。
例えば映像中央だけを使うには次の宣言にします。

```json
{ "id": "hand-camera", "cropX": 0.25, "cropY": 0.25, "cropWidth": 0.5, "cropHeight": 0.5 }
```

## Luaスキン

JSONと同じフィールドです。既存の `skin` テーブルへ追加します。

```lua
skin.camera = {{ id = "hand-camera" }}
table.insert(skin.destination, {
    id = "hand-camera", stretch = 3,
    dst = {{ time = 0, x = 940, y = 520, w = 320, h = 180 }}
})
```

## 取得・停止・検証

既存同梱FFmpeg executableを別プロセスで動かし、音声を取得せずRGB24映像だけを
本体へ渡します。描画スレッドでデバイスを開いたり映像を待ったりしません。
ワーカーは一つ、カメラプロセスは一つ、RGBバッファは三つ、未描画フレームは最新一つです。
GLではPixmapとTextureを再利用し、同一描画フレーム中のアップロードは一回です。

表示要求がなくなったフレームの終わり、アプリのpause、終了時に取得を停止します。
スキンが破棄／切替された場合も次の描画フレームで要求がなくなるため停止します。
子プロセスには終了を要求し、250ms後も生きていれば強制終了します。
JVM終了時にも残っている子プロセスを強制終了します。
起動や読み取りが10秒止まった場合も終了させます。スコア、リプレイ、IR、Arena通信には
カメラ映像を追加せず、この機能自体に録画・保存・送信機能はありません。
画面全体のスクリーンショットやOBS等での録画には、表示中の映像が含まれます。

非GUIテストは旧設定の既定OFF、設定永続化と上限、デバイス列挙結果の解析、
保存したカメラの名前・IDでの照合（番号や列挙順の変化、未接続、同名カメラ）、BGA枠表示の設定と取得要求、camera部品のあるスキンでのBGA枠表示の抑止、表示位置・拡大率・切り抜きの計算と保存、F5メニューの選択の保存と選択肢、JSON/Lua宣言、
切り抜き、フレームの完全性と最新フレーム、取得中の停止、起動中の停止、取得失敗の再試行間隔と後から挿したカメラ・挿し直したカメラへの自動再接続、
画面要求の消失、同梱FFmpegの合成赤映像とプロセス終了を確認します。実カメラは開きません。

実機受け入れはoperatorが行います。Windows/macOSで一覧・許可・拒否・取得失敗、
正しい色と上下・左右反転、切り抜きと伸縮、位置・枠・表示条件、選曲→プレイ→リザルトの
カメラ停止／再開、スキン切替、複数camera部品、画面最小化・終了、抜き差し、BGAとの
同時表示、通常プレイとArenaでの描画負荷・音切れを確認してください。
GUI／実カメラ確認を非GUIテストの成功だけで完了扱いにしません。
