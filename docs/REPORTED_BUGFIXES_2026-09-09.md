# 9月9日追加報告へのソース対応 (#371)

報告: https://github.com/BMS-Mania/IR/issues/478#issuecomment-5599425579

## HS増減

LR2固定が有効な場合、増減幅を開始時HSに掛けず、設定値をそのまま使う。
これによりリトライ時の開始HSが変わっても増減幅は変わらない。
通常の固定HSは従来の相対増減、固定OFFは絶対増減を維持する。
上下限、duration同期の条件、Start Here表示更新の条件は変更しない。

## 強制LNランキング

未定義LNのキャッシュ添字は、呼出側が保存済みCN/HCNを渡しても強制ONなら0とする。
明示CN/HCNを含む譜面・コースは従来どおり強制ON/OFFのキーを分離する。
設定は1操作につき1回読み、選曲のキャッシュ参照・登録・IR取得には同じ不変の
`IRRankingContext`を渡す。非同期取得のローカル比較スコアも開始時に保持する。

現行の通常選曲経路は既に`PlayerConfig.getLnmode()`で強制ONを0へ変換している。
したがって添付資料の「保存済みモードがそのまま渡る」という説明だけでは、
報告された表示を再現できていない。今回の自動検証はキャッシュ境界の正規化、
ON/OFFの分離、設定変更後も取得と保存先が一致することを対象とする。
実際の表示が解消したかは、配布後の実機確認で判断する。

## オーバーレイ入力

Arenaのボタン・テキスト操作後にフォーカスだけが残っても、鍵盤入力を捕捉しない。
テキスト入力要求、操作中の項目、外部IMEエディタによる捕捉は維持する。
既存Mod Menu・スキン管理・MANIAC設定を開いている間のキーボード操作捕捉も維持する。
ホットキー登録と、捕捉中に押したキーを離すまでゲーム入力へ戻さない処理は維持する。

## 確認

- `LaneRendererHispeedStepTest`: リトライを重ねても増減幅1/0.25が一定、通常固定の相対幅。
- `ForcedLnRankingTest`: 保存済みCN/HCN、未定義LN・混在コース、設定の読出し回数、取得時設定の保持。
- `ImGuiInputCaptureTest`: ボタン・編集完了後の解放、編集中・外部IME・既存メニューの捕捉。
- `core:test`、macOS ARM64の`core:shadowJar`、PR CI。

実機確認: LR2固定でHSを変更して複数回リトライし、増減幅とdurationを確認する。
CN/HCN取得済み／未取得の両方で強制ON/OFF/ON、選曲・リザルト・コースを確認する。
検索・チャットのEnter/Esc/外側クリックとHSボタン操作後にテンキーが戻ること、
編集中・IME中・ホットキー登録中はゲームへ入力が漏れないことを確認する。

この変更はソースのみ。実機確認・テスト配布は別工程とし、サーバーやプラグインは変更しない。
