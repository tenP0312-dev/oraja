# ナントカマニアモード

MANIAC OPTIONSの「ナントカマニアモード」（英語表示: NANTOKA MANIA MODE）を
ONにすると、5/7/10/14KEYのソロプレイ(単体使用時は段位認定コースも含む)で
下記の判定・ゲージ仕様を使う。初期値はOFF。
選曲でF2を長押しして開き、既存の「適用して戻る」操作で設定を保存する。
ゲージの種類は選択したものを使い、その増減と失敗条件を固定する。
DPの両皿にはDP専用の判定を適用する。

## 仕様と適用範囲

新規プレイにはユーザー提供の判定仕様と従来のゲージ仕様をBMS向けに適用する。
判定幅、入力候補、見逃し期限、長押し処理、整数ゲージの動作は以下の通り。

- 通常入力候補は −350msより後、+250ms以下。判定表のBAD外周と見逃し期限は別条件。
- 通常の判定プロファイル、譜面の判定ランク、判定幅拡大、Judge Trainer、GAMBOLは
  このモードの判定に影響しない。元の設定値は保存したまま、OFFにすると再び適用する。
- 既存のノーツ表示タイミング調整は表示だけに作用する。判定対象時刻の追加オフセットは0。
- ゲージ自動切替は一時的に無効。HARD/EX-HARD/HAZARDの失敗条件に従って終了する。
- 他のMANIAC譜面・表示オプションとは組み合わせ可能。ASSISTによる記録制限は維持する。
- Arena・PRACTICEでは適用しない。
- コースは、なんとかマニア単体(譜面改変系・DOUBLE BATTLE・DAN GAUGEなど他の
  MANIAC効果が全てOFF)の場合に限り適用する。判定・ゲージだけがこの仕様になり、
  譜面・曲順・段位の識別情報は変更しない。ただし**その段位の合否・スコア・リプレイ・
  IR送信は一切記録しない**(既存の「作業フォルダ」「7K TO 9K試遊版」と同じ、
  スコア無効化スイッチの扱い)。他のMANIAC効果を一つでも含む場合は従来通り
  コースでは完全に無効化する。
- Switchの段位ファイル探索、4曲段位画面、SURVIVALの移植やオンラインの専用
  ランキングは、この機能の対象外。

## 判定

時刻差は「入力時刻 − ノーツ時刻」。負がFAST、正がSLOW。
境界は `seed × 1000 / 60 + 0.25` ms、各区間は下端を含まず上端を含む。
実装は単精度で計算した境界を整数マイクロ秒へ投影して、この包含関係を保持する。

| 判定の外側境界（ms、概数） | 鍵盤 FAST / SLOW | SP皿 FAST / SLOW | DP皿 FAST / SLOW |
| --- | --- | --- | --- |
| PGREAT | −16.416667 / +16.916667 | 同左 | 同左 |
| GREAT | −33.083333 / +33.583333 | −66.416667 / +66.916667 | −99.750 / +100.250 |
| GOOD | −116.416667 / +116.916667 | −149.750 / +150.250 | −183.083333 / +183.583333 |
| BAD（テーブル） | −249.750 / +250.250 | −283.083333 / +283.583333 | −316.416667 / +316.916667 |

FAST側のBAD境界以下、−350msより後の入力は、同一レーンに未処理の候補がある場合だけ
空POORとする。ノーツを消費せずコンボを切らず、BAD相当のダメージを与える。
通常POORは仮想60Hzの整数フレーム差が15を超えた更新で発生する。鍵盤・皿共通。
ノート時刻を曲全体の60Hz格子へ切り下げ、16フレーム後を期限とする。
候補窓内の未判定ノーツは絶対時刻差が最小のものを優先する。同距離なら先行ノーツ。
未判定候補がなく判定済み候補だけが残る場合も空POORになる。1入力で先行BADを
追加処理するLR2orajaの仕組みは使わない。FAST/SLOW合計はGREATとGOODを数える。

LN/CN/HCN/BSSの始点と終点は各1ノーツ。元の長押し種別は変えない。
CN/LN始点がBADまたは見逃しなら終点を判定せずに処理済みとし、HCNでは本体と終点を
残すが、再入力は本体回復だけを再開し、終点保持を新たに作らない。
終点の基礎判定がGOOD以上ならPGREAT、BADならBAD、早い判定外なら通常POOR、
遅い判定外なら空POORとして終点を消費する。見逃し期限の処理が先に走るため、
遅い判定外の終点が通常操作で必ず到達可能という意味ではない。
旧LNはBMS向け規則として保持して終点に達すると自動PGREAT。
鍵盤HCNは早い途中離しでも直ちに終点を判定して消費する。
再保持は本体回復のみを再開し、消費済み終点を復活させない。
BSSは逆方向入力またはorajaの論理停止イベントで終点を判定する。
終点の消費後も未終了HCN本体の保持/非保持処理は続く。

## ゲージ

内部値は0〜5000の整数（1単位=0.02%）。通常数値と画像は2%刻み・50区画。
長押し終点を含む総ノーツ数Nから `E = N < 350 ? N : 350 + floor((N−350)/3)`、
`Rpg=floor(80000/(6E))`、`Rgood=floor(40000/(6E))` を求める。E=0なら回復量0。

| 種類 | 初期値 | PGREAT/GREAT | GOOD | BAD/空POOR | 通常POOR |
| --- | ---: | ---: | ---: | ---: | ---: |
| ASSIST EASY / EASY | 1100 | Rpg | Rgood | −80 | −240 |
| NORMAL | 1100 | Rpg | Rgood | −100 | −300 |
| HARD | 5000 | +8 | 0 | −250 | −450 |
| EX-HARD | 5000 | +8 | 0 | −500 | −900 |
| HAZARD | 5000 | +8 | +8 | 即失敗 | 即失敗 |

回復型は下限100、クリア境界はASSIST EASYが60%、EASY/NORMALが80%。
HARDは判定前1666未満ならダメージ半減。HARD/EX-HARDは更新後100未満で0にする。
100ちょうどは継続し、一度0になったゲージは回復しない。
共通計算器には資料のDAN値（+8/+2/−85/−125、1666未満は整数で半減）も定義する。
なんとかマニア単体でコースを起動した場合、CLASS/EXCLASS/EXHARDCLASSゲージは
この値で動く（起動条件と記録の扱いは「仕様と適用範囲」を参照）。

HCN本体は仮想60Hzの8フレーム周期（約133.333ms）を曲全体で共有する。
描画FPSや更新の分割に依存せず、同じ入力ログなら同じ周期・順序になる。
同時刻ではノーツ到達・見逃し、入力、共通tickの順で処理する。
非保持状態でtick境界に再入力した場合、その回の空POORを処理してから保持へ戻る。
本体終了はtickより先。終了後も終点保持と入力が残る間は回復し、終点消費/見逃しで止まる。
保持中はPGREAT回復量を全量加算、非保持中は空POORを1回記録してBADダメージを与える。
tickはEX SCORE、コンボ、ノーツ消費数を変えない。
orajaの通常POOR・空POORは別の保存欄なので、空POORを両欄へ二重計上しない。
BPとPOOR総数相当の表示は通常POORと空POORの合計を使う。
10フレーム周期（約166.667ms）では非保持のPOOR表示を更新、保持中は直前の表示時間を延長する。
表示更新は判定数・EX・コンボ・ゲージを増減させない。

## 記録と検証

ONの記録は `bmsir_maniac.db` の専用IDへ保存する。リプレイにも設定を保存し、
存在確認・読込・削除を同じ専用IDに統一する。通常記録と他のMANIAC記録は別扱い。
曲開始前から押していたキーの状態も保存し、再生時のHCN保持状態へ引き継ぐ。
OFF時の既存の設定文字列・記録IDは変更しない。
ONでは通常IR・MANIAC IRへの送信、所有者同期、Arenaへの持ち込みを許可しない。

新規プレイは `nantoka_version=2` を専用IDに含め、旧成績を上書きしない。
旧canonical文字列（バージョン指定なし）はv1。旧リプレイもv1で再生する。
新リプレイがないスロットでは旧リプレイを読み込めるが、新規保存はv2に書き込む。
他のMANIACのalgorithmやOFF時のIDは変更しない。
orajaでは60Hzの仮想格子、マイクロ秒入力、方向キーの押下/離上を使う。

自動回帰対象は全判定境界の前後、DP両皿、連打時の候補優先、長押し始終点、
HCN共有周期・再入力・見逃し、整数ゲージと失敗閾値、OFFのID互換、DB・リプレイ分離。
操作感、実コントローラーの皿方向、スキン上の表示は実機確認の対象。
実装時にはゲームを起動・操作せず、テストとmacOSビルド、PRのCIで検証する。
